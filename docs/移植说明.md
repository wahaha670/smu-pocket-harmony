# 南医大口袋 · 鸿蒙版（SMU Pocket for HarmonyOS）

> 由 Android 版 [1812355417/smu-pocket](https://github.com/1812355417/smu-pocket) 移植而来。
> 目标是 **HarmonyOS NEXT（纯 ArkTS / ArkUI 重写）**，不使用兼容层、不打包安卓 APK。

---

## 一、这是什么

南方医科大学学生的教务客户端，功能与原版对齐：

| 页面 | 能力 |
|---|---|
| **今日** | 日期标题 · 今日课程 · 明日课程（含跨周）· 本周概览柱状图 · 考试安排（含**网考号**） |
| **课表** | 固定 14 节网格（含 11~14 节晚课）· 按周切换 · 教务原生配色 · 跨节课程合并成整块 · 自主学习标注 |
| **成绩** | 按学期折叠 · 加权绩点 / 加权平均 / 总学分 / 门数 |
| **设置** | 手动同步 · 接入状态 · 退出登录 · 开发者与反馈 |

**扫码登录**：在 Web 组件里打开学校登录页，用户自己扫码；App 不接触密码，只接管登录成功后的 cookie。

## 二、技术栈对照

| 层 | Android 原版 | 鸿蒙版 | 说明 |
|---|---|---|---|
| 语言 | Kotlin 2.0.21 | **ArkTS** | 语法相近，但 ArkTS 更严格（无 `any`、无结构化类型） |
| UI | Jetpack Compose | **ArkUI 声明式** | 组件语义可一一对应 |
| 状态 | ViewModel + StateFlow | **@Observed + @ObjectLink** | 统一用状态管理 **V1** |
| 网络 | OkHttp + Retrofit | **@ohos.net.http** | 手写 cookie 管理与表单编码 |
| 存储 | SharedPreferences / 文件 | **@ohos.data.preferences / @ohos.file.fs** | 语义一致 |
| 日期 | java.time.LocalDate | **自实现 DateUtils** | ArkTS 无 java.time，用毫秒时间戳 |
| 登录 | android.webkit.WebView | **ArkUI Web 组件 + WebCookieManager** | 都是"开学校页面 + 捞 cookie" |

## 四、移植中必须知道的关键决定

这一节记录**为什么这么写**，改动前请先读完。

### 1. 状态管理统一用 V1，不要混用 V2

ArkUI 有 V1（`@State`/`@Prop`/`@ObjectLink`）和 V2（`@ComponentV2`/`@Local`/`@Monitor`）两套。
**同一工程里混用会直接编译失败。** 本工程全程 V1。

因此：

- 不能用 `@Monitor` 监听变化 → 改用**回调 prop** 上抛动作（`onSelectWeek` / `onSync` 等）
- 不能用 `CardBox(...) => { ... }` 这种 V2 尾随闭包 → 改用 `CardBoxHost({ body: () => {...} })`

### 2. 卡片容器为什么叫 `CardBoxHost`

V1 里跨组件传 `@Builder` 容易踩「`this` 指向丢失 → 内容不渲染」，
而 V2 的箭头写法又不合法。最稳的做法是**把普通函数当 prop 传进来**：

```typescript
CardBoxHost({
  isDark: this.isDark,
  body: (): void => { this.TodayCard(); }
})
```

### 3. 今日页与课表页必须解耦

- `state.scheduleCourses` = **课表页选中那一周**的课
- `state.currentWeekCourses` = **真实当前周**的课（今日页用）

用户在课表翻到第 8 周时，今日页仍然显示真实当前周的课。
**不要把这两个字段合并**，那是原版明确修过的 bug。

### 4. 课表网格永远渲染 14 行

行数不跟 `config.periods` 走，永远是 `TOTAL_SECTIONS = 14`。
原因：晚课排到 11~14 节，而旧缓存里作息只有 10 条 ——
按配置决定行数会让这些课**整块消失**。

### 5. 会话失效不是 401

教务 cookie 过期后，**不会返回 401**，而是 302 到登录页再回一个
**200 + 一整页登录 HTML**。所以 `looksLikeLoginPage()` 必须检查
「状态码 + URL 特征 + HTML 里有没有密码框」三者。
只看 `code === 200` 会拿 HTML 去 `JSON.parse`，报出误导性的解析错误。

### 6. `code: -401` 是业务码，HTTP 仍是 200

课表/成绩接口未登录时返回 `{"code":-401,"data":"","message":"尚未登录"}`。
解析器要能吃掉 `data` 是**空字符串**的形态，否则会抛
「Expected start of the array」这种看不懂的错。

### 7. 学期代码不能"取最大六位数"

教务成绩页下拉里混着 `203402`（2034 年）这种未来值。
早期实现取了最大值 → 所有请求用错学期 → **全部返回空数据**。
现在：**缓存 → 日期推算 → 常量兜底**，并用 `isPlausible()` 拦截异常值。

### 8. 成绩接口的 `rows` 与 `data` 平级

真实响应是 `{ "data": "", "rows": [...], "total": 50 }`，
`rows` 不在 `data` 里面。按嵌套结构写会得到空列表**且不报错** ——
这是最阴的一类 bug。解析器同时兼容两种形态。

### 9. 成绩必须分页

`total=50` 但默认只返回 20 行。不翻页会**静默少数据**。

### 10. 网考号字段名会骗人

抓包时看到的是 `xkh`，真实响应里网考号在 **`xid`**。
两个都解析，`xkh` 优先、回退 `xid`。

## 五、构建与运行

### 前置条件

| 项 | 要求 |
|---|---|
| DevEco Studio 或 Command Line Tools | 见 `环境安装.md` |
| HarmonyOS SDK | API 12（5.0.0）或更高 |
| 真机 | HarmonyOS NEXT 设备，已开启开发者模式与 USB 调试 |

### 命令行构建

```powershell
# 用本机已有的 devecocli 包装脚本
$cli = '$env:APPDATA\xiaoyiwork\connectors\deveco\devecocli.cmd'

# 1. 检查设备
& $cli device list

# 2. 编译
& $cli build --project-path D:\HarmonyOS\smu-pocket

# 3. 安装并运行（需先签名）
& $cli run --project-path D:\HarmonyOS\smu-pocket --device <序列号>
```

### 签名

鸿蒙安装到真机需要签名。首次：

```powershell
& $cli auth login                                          # 浏览器登录华为开发者账号
& $cli signature generate --product default                # 自动生成 p12/csr/cer/p7b 并写入 build-profile.json5
```

> ⚠️ `signature generate` 要求**已连接真机**（要读设备 UDID 注册调试证书）。

### 用 DevEco Studio 打开

`File → Open` 选 `D:\HarmonyOS\smu-pocket`，它会自动补全 SDK 与 hvigor 依赖。

## 七、已知差异与限制

| 项 | 说明 |
|---|---|
| **未做电费查询** | 原版也没有（电费走微信公众号 OAuth，WebView 拿不到） |
| **只读** | 与原版一致，不做选课/缴费/评教等写操作 |
| **作息表本地维护** | 教务没有「每节课几点上」的接口，`Periods.ets` 里的 1~14 节是按真实抓包校准的 |
| **固定 14 节** | 学校若新增第 15 节及以后，需同步调大 `TOTAL_SECTIONS` |
| **未做上课提醒** | 原版 Android 也没有实现（架构文档里是 P6 计划项） |
| **深色模式** | 跟随系统；未做 Android 12+ 的「壁纸动态取色」（鸿蒙无对应 API） |
