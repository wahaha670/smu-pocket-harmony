## 2. 硬性限制（决定成败，务必先看）

### 2.1 event 只有 15 个场景，没有「上课」

从 `@hms.core.liveview.liveViewManager.d.ts` 逐字确认，`LiveView.event` 只支持：

```
TAXI 打车 · DELIVERY 外卖 · FLIGHT 航班 · TRAIN 高铁 · QUEUE 排队
PICK_UP 取餐 · SCORE 比分 · RENT 租赁 · TIMER 计时 · WORKOUT 运动
NAVIGATION 导航 · CHECK_IN 打卡 · EXPRESS 快递 · PROGRESS 进度 · TRADE 交易
```

**全部是商业/出行场景，没有教育、课表、上课。**
本项目采用 **`TIMER`（计时/倒计时）** —— 它是白名单里唯一能表达
「距某时刻还有多久」的通用场景，语义最贴近，且不涉及位置权限。

### 2.2 必须向华为申请权益（无法绕过）

参照 [华为官方问答](https://developer.huawei.com/consumer/cn/forum/topic/0202192903315215865)：

| 阶段 | 条件 | 有效期 |
|---|---|---|
| **白名单调试** | 把设备加入白名单 | 90 天 |
| **调试权限** | 应用月活 < 1000 且未上架 | 60 天，可延期一次 |
| **正式权限** | 月活 ≥ 1000 + 已上架 + 设计评审（7 个工作日） | 长期 |

场景上限：单次最多申请 3 个，同一应用最多 11（部分文档写 8）个。

> **对本项目的现实含义**：这是个人自用 App，既没上架也没月活，
> 只能走白名单调试（90 天）或调试权限（60 天）。
> **到期后实况窗立即失效**，需要重新申请。

### 2.3 权限不在 manifest 里，而在 AGC Profile 里

这是最容易走弯路的一点，已实测确认：

- `liveViewManager.d.ts` 全文 **没有任何 `@permission` 标注**；
- 本机 SDK 的 `PermissionDefinitions.json` 里 **没有** `LIVEVIEW_CONTROL`、
  `REAL_TIME_ACTIVITY` 这类权限（网上文章提到的这两个都查无此项）；
- 实测往 `module.json5` 加 `"capabilities": [{"name": "ohos.capability.liveView"}]`
  会**直接 Schema 校验失败、编译不过**（`00303038 Configuration Error`）。已回退。

结论：**实况窗准入走 AGC 给应用 Profile 下发的能力**，不是工程侧声明权限。
开通后需**重新生成 Profile 并重新打包**，否则包里的 Profile 仍无该能力。

## 3. 已实现的代码

### 3.1 `entry/src/main/ets/core/LiveView.ets`（新增）

| 函数 | 作用 |
|---|---|
| `probeLiveView()` | 探测可用性；能识别「总开关未开」与「本机不支持」 |
| `buildContent(course, leadMinutes)` | 生成标题/副标题/倒计时文案 |
| `startCourseLiveView(course, leadMinutes)` | 创建实况窗；**失败返回中文说明，不抛异常** |
| `stopCourseLiveView(course)` | 结束单个 |
| `stopAllCourseLiveViews(courses)` | 批量结束 |

关键实现点：

- **倒计时**用 `timer: { time: <距提醒时刻的毫秒>, isCountdown: true }`，
  配合 `TimerCapsule` 实现「还有 15 分钟」的实时倒数；
- **id 稳定**：用 `FNV-1a(课程id + 星期 + 起始节)` 压到 int32，保证同一节课
  反复创建/更新用同一个 id，不会堆出一堆僵尸卡片；
- **时间来源**优先用教务给的 `course.timeLabel`（如 `08:30-10:00`，比作息表准），
  缺失时回落到 `DefaultPeriods.at(startSection)`；
- **错误码分流**：
  - `1003500005` → 「未开通实况窗权限：需在 AGC 申请场景权益」
  - `1003500004` → 「系统实况窗总开关未打开」
  - `1003500006` → 已存在，先 `stop` 再重建
  - `1003500008` → 每秒创建过多，用 20ms 间隔规避
- **绝不拖垮主流程**：所有失败都返回字符串而非抛异常。

### 3.2 设置页（`ui/settings/SettingsScreen.ets`）

新增「开课前实况窗提醒」卡片：

- 开关（`Toggle`）
- 提前分钟数：**5 / 10 / 15 / 30** 四档可点选（默认 15）
- 状态文案：实时显示「未开通权限」「总开关未开」「已为 N 门课创建」等

### 8.3 两个隐蔽的坑

**① `clickAction` 的 WantAgent 类型来源很绕**

`LiveViewKit` 的 `.d.ts` 第 8 行写死：
```typescript
import type { WantAgent } from '@ohos.wantAgent';   // 旧版模块
```
但**旧版 `@ohos.wantAgent` 没有导出 `WantAgentInfo` 类型**，导致没法直接用它构建。
试过并失败的组合（别再重复）：

| 写法 | 结果 |
|---|---|
| `import { wantAgent } from '@kit.AbilityKit'` | ❌ 无 `WantAgent` 成员 |
| `wantAgent.WantAgentInfo`（旧版） | ❌ namespace 里没有 |
| `@ohos.wantAgent/src/wantAgent/wantAgentInfo` | ❌ 模块路径不存在 |
| `import type { WantAgentInfo } from '@kit.AbilityKit'` | ❌ kit 没导出 |

**正解**（已编译通过）：用**新版** `@ohos.app.ability.wantAgent` 构建，
运行期与旧版同构，直接赋给 `clickAction`：
```typescript
import abilityWantAgent, { WantAgent as AbilityWantAgentType }
  from '@ohos.app.ability.wantAgent';
import type Want from '@ohos.app.ability.Want';

const infos: Array<Want> = [{ bundleName: 'com.smu.pocket', abilityName: 'EntryAbility' }];
const info: abilityWantAgent.WantAgentInfo = {
  wants: infos,
  actionType: abilityWantAgent.OperationType.START_ABILITY,
  requestCode: <n>,
  actionFlags: [abilityWantAgent.WantAgentFlags.UPDATE_PRESENT_FLAG],
};
const agent = await abilityWantAgent.getWantAgent(info);
```
⚠️ ArkTS 要求数组元素类型可推断，必须显式写 `Array<Want>`，否则报
`arkts-no-noninferrable-arr-literals`。

**② 图标只能写 `/resources/rawfile` 下的文件名**

`nodeIcons` / `icon` / `indicatorIcon` 传的是**文件名字符串**，不是 `$r()` 资源。
路径不对系统会静默降级成默认应用图标。本工程已放入：
```
entry/src/main/resources/rawfile/node_icon.png
entry/src/main/resources/rawfile/liveview_icon.png
```
