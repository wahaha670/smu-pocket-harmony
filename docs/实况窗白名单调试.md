# 实况窗 · 白名单调试（设备联调）操作指南

> 目标：让 `com.smu.pocket` 在你自己的 Mate 80 Pro Max 上**免审批**跑起实况窗。
> 白名单调试是目前唯一 **不需要应用上架、不需要月活** 的路径。

**代码侧我已经全部写好并编译通过（BUILD SUCCESSFUL）**，你只需要去 AGC 后台操作 + 填一个 Client ID。

---

## 0. 先搞清楚三个容易踩的认知

| 误区 | 事实 |
|---|---|
| 「白名单是按设备 UDID 加的」 | ❌ **按 Push Token 加的**，不是 UDID。UDID 只用于签名证书 |
| 「加了白名单马上生效」 | ❌ **24 小时内生效**。生效前依然报没权限 |
| 「加白名单就够了」 | ❌ 还要先**开通推送服务** + 工程里配 **client_id**，否则连 Token 都取不到 |

> 官方原文要点（[接入联调测试](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/liveview-joint-commission-test)）：
> 「添加到调测名单中的设备，**不做本地构建实况窗权限的校验**」；
> 「调测设备管理名单数据，系统将在 **24 小时内**处理并生效」；
> 「调测设备管理需**根据 Push Token** 添加，每个应用上限 **100** 台」。

## 1. 完整流程（五步）

```
① AGC 开通推送服务
        ↓
② 拿到 Client ID → 填进 module.json5（我已留好占位符）
        ↓
③ 重新签名装包 → App 里「获取 Push Token」→ 复制
        ↓
④ AGC：实况窗 → 白名单设备管理 → 用 Token 添加设备
        ↓
⑤ 等 24 小时 → 打开实况窗开关，验证
```

---

## 2. 第①步：开通推送服务

1. 登录 [AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)
2. **我的项目** → 选中你的项目（`com.smu.pocket` 所在的那个）
3. 左侧 **增长 → 推送服务**
4. 点 **「立即开通」**

> **为什么必须开推送？** 白名单是按 Push Token 添加的，而 Push Token
> 只能由 Push Kit 发放。不开推送服务就取不到 Token。

---

## 3. 第②步：把 Client ID 填进工程

### 3.1 去哪拿 Client ID

AGC → **我的项目** → **项目设置** → **常规** → 「应用」区块 →
**OAuth 2.0 客户端 ID（凭据）** 里的 `Client ID`。

### 3.2 填到哪

我已经在 `entry/src/main/module.json5` 里留好位置：

```json5
"metadata": [
  {
    "name": "client_id",
    "value": "PASTE_YOUR_CLIENT_ID_HERE"   // ← 换成你的 Client ID
  }
]
```

**注意**：必须写死字符串，**不能用 `$string` 引用资源**（官方 FAQ 明确）。

### 3.3 还要上传签名证书指纹（关键，很容易漏）

AGC → 项目设置 → 常规 → 应用 → **添加公钥指纹**（选 HarmonyOS API 9 及以上）。
不上传指纹，取 Token 会报 `1000900010 Illegal application identity`。
**指纹上传后需 30–60 分钟生效**，别急着测。

---

## 4. 第③步：装包并取 Push Token

1. 重新签名打包装到手机（签名配置需先跑一次 `signature generate` 写回）
2. 打开 App → **设置** → 「开课前实况窗提醒」卡片 → 点 **「获取 Push Token」**
3. 成功后点 **「复制」**

> 代码已实现（`core/PushToken.ets`）：失败会把错误码翻成中文，比如
> `1000900010` 会提示「检查 AGC 是否开通推送服务、client_id、签名指纹」。

---

## 5. 第④步：在 AGC 加白名单

1. AGC → **我的项目** → 你的项目
2. 左侧 **增长 → 推送服务 → 配置**
3. 选中你的应用 → 点 **实况窗 → 白名单设备管理**
   （部分界面叫「调测设备管理」）
4. 粘贴刚才复制的 **Push Token** → 添加

上限 100 台，个人用 1 台足够。

---

## 6. 第⑤步：等生效并验证

- **等待 24 小时**（官方明确写 24 小时内处理生效）
- 想立刻测？官方 FAQ 给了一个土办法：
  > 「如果需要立即调试，可以修改手机系统时间至 24 小时后。」
  ⚠️ 改系统时间会影响课表日期计算，用完记得改回来。

生效后：

1. 打开 App → 设置 → 打开「开课前实况窗提醒」开关
2. 顶部状态栏应出现**倒计时胶囊**，锁屏/通知栏出现课程卡片
3. 若仍报 `1003500005`，说明白名单还没生效或 Token 填错

---

## 7. 白名单的能力边界（要知道）

| 能力 | 白名单下可用？ |
|---|---|
| 本地创建/更新/结束实况窗 | ✅ **可用**（我们只用这个） |
| UI 展示效果验证 | ✅ 可用 |
| 通过 **Push Kit 远程**推送更新 | ❌ **不支持** |
| 有效期 | 与 **Push Token 有效期一致**（官方表述），非固定 90 天 |

> 我们这套课表提醒是**纯本地创建**（App 内直接调 `startLiveView`），
> 不依赖 Push Kit 下发，所以白名单完全够用。

---

## 8. 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `1000900010` Illegal application identity | client_id 错 / 没开通推送 / 证书指纹没传或未生效（等 30–60 分钟） |
| 拿到 Token 但加白名单报错 | Token 复制不完整；重新复制 |
| 加了白名单还是 `1003500005` | **24 小时还没到**；或 Token 属于别的包名 |
| 换手机/重装后失效 | Push Token 变了 → 用新 Token 重新加白名单 |
| 报 `1003500004` | 用户把系统实况窗总开关关了 |
