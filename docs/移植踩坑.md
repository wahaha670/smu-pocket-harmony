# 移植踩坑记录

从 Android（Kotlin + Compose）移植到 HarmonyOS NEXT（ArkTS）过程中踩过的坑，
按类别整理。**每条都注明症状与修法**，供后来者少走弯路。

> 编号仅为顺序，不代表重要性。⚠️ 标记的是最隐蔽、最难排查的那些。

---

## 一、环境类

### 1. 路径含中文 = 编译失败

```
The argument value 'D:\下载\...' is not an ASCII value
```

华为的 `restool` 不接受非 ASCII 路径。**工具链和项目都必须放在纯 ASCII 路径下**
（本项目用 `D:\HarmonyOS\`）。

### 2. `D:\下载` 带 ReadOnly 属性无法 rename

想移动目录时 `Move-Item` 被拒。用 `robocopy /E /MT:32` 复制绕过。

### 3. 缺 `hvigor/hvigor-config.json5`

hvigor 启动即报 `00304004 Not Found`。该文件不在 DevEco 生成的模板里，
需要手建（`modelVersion` 与本机 hvigor 版本匹配）。

### 4. devecocli 的登录/签名被代理阻断 ⚠️

```
Error: Hostname/IP does not match certificate's altnames: Host: localhost.
Network connection failed (ERR_TLS_CERT_ALTNAME_INVALID).
```

Clash 把 `localhost` 的登录回调也代理了，TLS 证书校验失败。
**`NO_PROXY` 里写了 `localhost` 也没用**，devecocli 不遵守。

更坑的是：这个故障**同时影响 `auth status`**，它会一直误报「未登录」，
让人以为登录没成功，实际是查询本身被代理挡了。

**修法**：跑任何 devecocli 命令前先清代理变量。

```powershell
Remove-Item Env:HTTP_PROXY,Env:HTTPS_PROXY,Env:http_proxy,Env:https_proxy -ErrorAction SilentlyContinue
$env:NODE_USE_ENV_PROXY='0'
```

### 5. 安装报 `install already exist` 但应用其实没装

错误码 `9568276`。`bm dump -n <bundle>` 查不到、`bm uninstall` 也说
"uninstall missing installed bundle"，但 `devecocli run` 就是装不上。

**绕过**：直接用 hdc 装签名好的 HAP。

```powershell
hdc -t <device> install -r entry-default-signed.hap
```

## 二、代码类（ArkTS 比 TypeScript 严格得多）

### 6. 请求体字段是 `extraData`，不是 `data`

HarmonyOS 的 `HttpRequestOptions` **没有 `data` 字段**，传了会被忽略（不报错）。

### 7. `configCookieSync(url, '')` 是清空 cookie，不是 flush ⚠️

想「保存 cookie」时写了这个，结果把刚拿到的登录态**清掉了**。
正确的是 `saveCookieSync()`。另外需要 `putAcceptThirdPartyCookieEnabled(true)`
才能接住第三方登录页的 cookie。

### 8. `@Observed` 状态对象不能整体替换 ⚠️

`this.state = new AppState()` 会**断掉 `@ObjectLink` 的绑定**，
界面从此不再更新。必须原地重置 —— 加一个 `AppState.reset()`。

### 9. 禁用 `any` / `ESObject`

`arkts-no-any-unknown`。解析未知 JSON 时用 `Object` + `Record<string, Object>`
配合显式类型判断。

### 10. 构造函数不能写 `constructor(private x: T)`

`arkts-no-ctor-prop-decls`。要拆成独立的字段声明 + 赋值。

### 11. 字符串不能下标访问

`arkts-no-props-by-index`。`labels[i]` 不合法，要用 `string[]` 数组。

### 12. `@BuilderParam` 只接受尾随闭包

`this.body()` 这种写法不合法。

### 13. `ColorMode` 是数字枚举

`ConfigurationConstant.ColorMode.COLOR_MODE_DARK = 0`（不是字符串）。
在 `@Entry` 组件里 `onConfigurationUpdate` 的参数类型与声明不完全一致，
直接比较会被 TS 判为「string 与 ColorMode 无重叠」——
本项目把类型细节收敛进 `prefersDark()` 一个函数里。

### 14. 导入语句必须在所有其它语句之前

`arkts-no-misplaced-imports`。把 `const` 定义插在 import 中间会报错。

## 三、运行时类（真机 / 模拟器实测发现）

### 15. 课表切周后网格不刷新 ⚠️

`ForEach` 的键只用了 `星期_序号`，切周时内容变了但键没变，
ArkUI 判定「同一批组件」直接复用，不重新渲染。

**修法**：键里带上**课程 id + 跨度**，并把格子拆成 `@Prop` 独立组件
（`@Builder` 按值传参不会随参数变化重新求值）。

### 16. 沉浸式全屏导致标题与状态栏重叠

`setWindowLayoutFullScreen(true)` 却没做安全区偏移 → 改回 `false`。
（后来为了底部系统栏适配又改了窗口背景色，见 [深色模式.md](./深色模式.md) 第六节。）

### 17. 底部导航无固定高度时点击失效

Column 没有高度，点击热区塌陷。加 `height(58)` + 扩展点击区。

### 18. 卡片右侧溢出屏幕

`CardBox` 不能同时用 `width('100%')` 和左右 margin ——
实际宽度会变成 `100% + 28`。改用 `width('auto')` 让 margin 从父宽里扣。

### 19. `Scroll` 默认居中对齐内容 ⚠️

内容比视口短时整块被**垂直居中**（设置页顶部凭空多出 170px 空白）。
修法：显式 `.align(Alignment.Top)`。**长屏手机上这个问题更明显**，
矮屏上内容本来就撑满，看不出来。

### 20. `onClick` 挂在 `@Component` 外层不生效

`CardBox` 是独立组件，事件不穿透；要挂在它内部那一层容器上。

### 21. 教务的 `bgcolor` 不能直接用来区分课程 ⚠️

实测 220 条数据**只有 4 种颜色**，其中一种占 60%；
且**同一门课在不同周颜色还会变**（「呼吸系统」出现过 4 种）。

**修法**：按**课程名哈希 + 冲突探测**自己分配颜色，
保证同课同色、异课异色（见 `core/CourseColors.ets`）。

### 22. 两种查询返回的课程 id 形态不同，不能用 id 去重 ⚠️

```
整学期总表：100037_TMP849_3_10_4        （教务课程码）
按周查询：  103868440_W117202601001_6_4_11
```

按 id 匹配永远失败 → 旧条目不被替换、新条目又 append →
**同一节课在缓存里出现两次**。

**修法**：改用业务键（课程名 + 星期 + 起止节）匹配。

### 23. 按周才有的字段要单独合并 ⚠️

`sknrjj`（上课内容）只有按周查询返回（实测 16/16），整学期总表仅 43/220。
**修法**：每次联网拿到某周后，把 content 等富字段**合并进整学期缓存**再落盘，
越用越全。

## 四、桌面卡片类

### 24. 卡片里 `@Builder` 带参数 = 数据到了但列表永远空白 ⚠️⚠️

ArkUI 的 `@Builder` **按值传参时不会随参数变化重新求值**。
卡片首次渲染时 `@LocalStorageProp` 还是默认值（`'[]'`），
`@Builder` 把空值**捕获死了**；等真实数据到达、`build()` 重跑时，
它的参数并不会更新。

症状特别迷惑：**标题有数据、课程列表永远空**，
但把 JSON 长度直接打在界面上又是对的（因为那是成员访问，不是参数）。

**修法**：课程行改用 `@Component` + `@Prop`，
两栏内容**内联在 `build()` 里**直接读 LocalStorage 属性，不经 `@Builder` 中转。

### 25. 卡片不能用带文件/网络能力的模块 ⚠️

卡片对可用 API 有严格限制。`WidgetData.ets` 里 import 了 `@ohos.file.fs`，
一旦被卡片引用，**编译卡片时直接报错**。
所以卡片内的 JSON 解析要单独写一份，只保留纯逻辑。

### 26. App 侧拿不到运行中卡片的 formId，但可以用 `reloadForms` 批量刷新

`formProvider.getFormsInfo` 只能查「声明了哪些卡片」，不是运行实例。
主动刷新要用：

```typescript
formProvider.reloadForms(context, moduleName, abilityName, formName)
```

它按「模块 + Ability + 卡片名」批量通知，**无需枚举 formId**，
返回值是本次请求更新的卡片数。

> 排查心得：曾误判这个接口没生效，实际上链路一直是通的。加日志后确认：
> ```
> SmuPocketWidget: reloadForms ok, count=2
> SmuPocketForm:   updateForm ok today=4 tomorrow=4
> ```
> 当时的「卡片没更新」是自己的**测试时序**问题 ——
> 卡片是在数据文件更新**之前**添加的，中间没有重启 App 触发刷新。
> **改完代码要重新触发一次刷新再观察，别急着下结论。**

### 27. 卡片里不能用 `Scroll`，但 `List` 可以 ⚠️

写 `Scroll` 时编译器直接拒绝：

```
'Scroll' can't support form application
```

改用 `List` 即可（官方文档也建议控制 list-item 数量以获得好的卡片交互体验）。
两栏各放一个 `List`，就能做到**左右独立滚动**。

### 28. 卡片交互只能在桌面上测，负一屏的卡片预览区不响应手势 ⚠️

在负一屏的「卡片」管理区里，卡片能正常渲染实时数据，
但**滑动、点击都不生效** —— 那是预览，不是部署的卡片。
因此一度误判「卡片不支持滚动」。

**正确做法**：长按应用图标 →「卡片」→「添加至桌面」，
然后在**桌面上**的卡片上测手势。

### 29. `navigationBarColor` 在手势导航下会被系统静默忽略 ⚠️

想让底部系统栏区域和 App 配色一致，设
`setWindowSystemBarProperties({ navigationBarColor })` **无效**。
查 hilog 才看到该项在系统侧是 `null`：

```
WMSImms: update prop ..., prop:[5,true,"#FF101215","#FFECEEF1",false,false,null]
                                                                          ↑ null
```

真正生效的是 **`setWindowBackgroundColor()`** —— 系统栏区域透出的是窗口背景色。
取 `surface`（与底部导航栏同色）才能消除接缝。
详见 [深色模式.md](./深色模式.md) 第六节。

## 五、通用经验

1. **编译器是权威**：想知道组件在卡片里能不能用，直接写一次看报错，
   比翻文档快（`'Scroll' can't support form application` 就是这么发现的）。
2. **布局工具不可靠**：`devecocli ui layout --format json` 会间歇性返回空，
   像素分析截图是可靠兜底。
3. **截图坐标要量不要猜**：我按目测给的坐标偏了 165px 点错菜单项；
   用像素扫描定位文字行中心后就准了。
4. **加日志再下结论**：多次因为「看起来没生效」而误判接口坏了，
   实际是自己的测试时序问题。先打日志确认链路。
