## 三、新增功能（真机实测）

### 功能 1：课表标题带月份 + 表头带日期

**需求**：大字加粗的「第 N 周」后面加月份；星期下面加该天日期；
跨月时标题用**前一个月份**，下方日期照常。

**实现**：

`AppViewModel` 新增三个派生方法：

```typescript
selectedWeekDates()          // 选中周的 7 个日期（周一 → 周日）
selectedWeekTitleMonth()     // 标题月份 = 周一所在月（天然满足「跨月取前一个」）
selectedWeekSpansTwoMonths() // 是否跨月
```

关键点：`selectedWeekTitleMonth()` 直接取 `dates[0]`（周一）的月份。
第 9 周周一在 10/26、周日在 11/1 → 标题显示「10月」，跨月规则自动成立。

**视觉细节**：
- 今天：实心圆底 + 白字
- 跨月的日期：下方加小圆点
- 表头与网格之间有分隔线

**实测**：

| 周次 | 标题 | 日期 | 是否跨月 |
|---|---|---|---|
| 第 11 周 | 第 11 周 · 11月 | 9–15 | 否 |
| 第 9 周 | 第 9 周 · **10月** | 26–31, **1** | ✅ 标题取前月 |
| 第 14 周 | 第 14 周 · 11月 | 30, 1–6 | ✅ |
| 第 15 周 | 第 15 周 · **12月** | 7–13 | ✅ 标题取前月 |

### 功能 2：整学期课表记忆（登录一次，全程离线可用）

**需求**：登录一次后记住所有课表，登录失效时课程内容和顺序不能乱。

**实现**：

1. **缓存结构升级**（`CacheStore`）
   - `CachedSnapshot` 新增 `termCourses` 字段，存整学期全部课程
   - version 从 1 升到 2

2. **修复 id 漂移**（这是「顺序混乱」的真正根源）
   ```typescript
   // ❌ 修复前：用数组下标生成 id
   id: `cache_${c.dayOfWeek}_${c.startSection}_${index}`
   // 同一门课在不同周/不同快照里 id 不同 → 合并去重时被当成两门课
   
   // ✅ 修复后：把真实 id 一并落盘
   id: c.id !== undefined && c.id.length > 0 ? c.id : `cache_${...}_${c.name}_${index}`
   ```

3. **离线周视图**（`loadWeek` 改造）
   - 切周时**优先**用本地 `termCourses` 过滤，秒开
   - 有本地数据 + 无会话 → 直接展示，不再等网络
   - 有本地数据 + 有会话 → 先展示本地，再后台拉最新
   - 网络失败但本地有数据 → 继续显示，不报错打断

4. **增量合并**（`mergeIntoTermCache`）
   - 联网成功拿到某周 → 并进整学期缓存，按 id 去重
   - 这样浏览过的周会被永久记住

**实测数据**（真机、真实教务）：

```
cache_snapshot.json = 75 KB
termCourses = 220 条
覆盖周次 = 1 ~ 20 周（完整）
带 id 条目 = 220/220
```

**关键验证：删除 session 模拟登录失效**

| 场景 | 结果 |
|---|---|
| 未登录启动 | ✅ 今日页还原第 11 周，课程完整 |
| 未登录 → 第 14 周（缓存态） | ✅ 10 节，跨月圆点正常 |
| 未登录 → 第 15 周 | ✅ 11 节，切到 12月 |
| 未登录 → 跳到第 3 周 | ✅ 15 节，9月，内容完整 |

**用户可见变化**：副标题会显示「· 离线缓存」，
让用户知道数据来自本地而非最新拉取。

**已知取舍**：网考号只在内存中，不落缓存（号码跟会话变，缓存旧号反而误导）。
所以离线时考试安排只显示课名、不显示号码 —— 与原版设计一致。

## 四、发现并修复的 bug

### Bug 0（真机实测发现）：课表切周后网格不刷新 ⚠️ 严重

**现象**（用户实测反馈）：点「下一周」或顶部周次条，
**标题变成「第 12 周」、副标题也变成「该周 14 节」，但下面的课表网格一动不动**，
还是上一周的课。

> 这是最隐蔽的一类 bug：**数据层完全正常，UI 层不重建**。

**原因**：`ForEach` 的键设计错误。

```typescript
// ❌ 修复前
ForEach(this.cellsOfDay(day), (cell, idx) => { ... },
  (cell: GridCell, idx: number) => `cell_${day}_${idx}`)
```

键只有「星期 + 序号」。切周后格子数量、内容都变了，
但键还是 `cell_1_0`、`cell_1_1`……，
**ArkUI 判定「键相同 = 同一批组件」，直接复用旧节点、不重新渲染**。

这完美解释了现象差异：
- 标题 / 「该周 N 节」→ 普通 `Text` 绑定 → 会更新 ✅
- 课表网格 → `ForEach` 列表 → 键没变 → 不更新 ❌

**修复（两层保险）**：

**第一层：键里带上内容标识**

```typescript
// ✅ 修复后
private cellKey(day: number, cell: GridCell, idx: number): string {
  if (cell.course !== null) {
    // 有课：带课程 id（含课程码/周次）和跨度，切周必变
    return `c_${day}_${cell.section}_${cell.course.id}_${cell.span}`;
  }
  // 空格子：用节次区分
  return `e_${day}_${cell.section}_${idx}`;
}
```

**第二层：格子改成独立 `@Component`**

把原来的 `@Builder CourseCell(course, height)` 换成独立的
`CourseCellView` 组件，用 `@Prop` 接收**扁平的原始类型**：

```typescript
CourseCellView({
  name: course.name,
  room: course.room ?? '',
  isSelfStudy: course.isSelfStudy === true,
  color: this.cellColor(course),
  cellHeight: height,
  // ...
})
```

为什么两层都要：
- `@Builder` 是「当前组件内的一段 UI 片段」，被 `ForEach` 复用时
  参数变了未必重新求值；
- `@Prop` 组件有**明确的「入参变 → 重新渲染」语义**；
- 传扁平原始类型（而非整个 `Course` 对象）避免 `@Prop` 浅比较漏更新。

**验证**（真机、真实教务数据）：

| 操作 | 结果 |
|---|---|
| 下一周 11 → 12 | ✅ 16 节 → 14 节，课程全换（呼吸系统 → 综合高级英语 / 医学专业英语） |
| 点周次条 12 → 8 | ✅ 变成 14 节，出现橙色「医学专业英语 [自主]」、绿色「类器官技术」 |
| 上一周 8 → 7 | ✅ 变成 12 节，出现绿色「循环系统」见习、蓝色「皮肤科中医外治法」 |

### Bug 1：标题与状态栏重叠

**现象**：课表页「第 6 周」标题被状态栏时间覆盖。

**原因**：`EntryAbility` 里调了 `setWindowLayoutFullScreen(true)`（沉浸式全屏），
但页面没有做安全区偏移，内容顶到了状态栏下面。

**修复**：改为 `setWindowLayoutFullScreen(false)`，用系统默认布局自动避让。

```typescript
// entry/src/main/ets/entryability/EntryAbility.ets
win.setWindowLayoutFullScreen(false);
```

### Bug 2：底部导航点击无响应

**现象**：点击「成绩 / 设置」Tab 无反应，页面停在课表页。

**原因**：底部导航的 `Column` 没有固定高度，实际高度被压缩到很小；
同时底部系统手势区会拦截点击事件。

**修复**：给每个 Tab 和导航栏容器都加固定 `height(58)`，
并把点击区域扩展到整个 Column（`.justifyContent(FlexAlign.Center)`）。

```typescript
// entry/src/main/ets/ui/RootScreen.ets
Column() { ... }
  .height(58)
  .justifyContent(FlexAlign.Center)
  .onClick(() => { this.currentTab = idx; })
```

> 另一个坑：点击坐标太靠下会触发系统「小艺对话」引导浮层
> （长按底部导航条触发）。验证时注意避开最底部约 40px。

## 四、模拟器的已知局限

| 项 | 说明 |
|---|---|
| **扫码登录** | 模拟器能打开 Web 页，但**无法真的扫码**（需要真实学校账号） |
| **真实接口** | 演示模式验证了 UI 与逻辑；真实教务接口需真机 + 账号验证 |
| **性能** | 模拟器比真机慢，动画流畅度不代表真机表现 |
| **系统能力** | 振动、传感器等硬件能力无法验证 |
