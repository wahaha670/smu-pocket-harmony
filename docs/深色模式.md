# 深色模式适配说明

> 覆盖范围：今日 / 课表 / 成绩 / 设置 四个页面 + 登录页 + **桌面卡片**
> 验证方式：模拟器切系统深色模式后逐页截图比对

---

## 一、两条独立的实现路径

App 页面和桌面卡片**走的是两套完全不同的机制**，改的时候不要互相套用。

| | App 页面 | 桌面卡片 |
|---|---|---|
| 机制 | ArkTS 状态管理 | **资源限定词目录** |
| 入口 | `prefersDark(context)` → `@Prop isDark` | `form_config.json` 的 `"colorMode": "auto"` |
| 取值 | `Theme.colors(isDark).xxx` | `$r('app.color.card_xxx')` |
| 资源 | 代码里的 `LIGHT` / `DARK` 两套常量 | `resources/base/element/color.json` + `resources/dark/element/color.json` |

**为什么卡片不能用 `Theme`**：卡片运行在独立的 FormExtensionAbility 里，
对可用 API 有严格限制，不能引用带文件/网络能力的模块（详见 `WidgetCard.ets` 头注释）。
所以卡片只能用系统资源限定词，让系统按当前色彩模式自动挑对应目录下的值。

## 二、App 侧的链路

```
系统切换深色
  → Index.ets 的 onConfigurationUpdate()
  → prefersDark(context) 重新求值
  → @State isDark 更新
  → 逐层 @Prop 传给各页面
  → Theme.colors(isDark) 返回 LIGHT 或 DARK
```

`onConfigurationUpdate` 里**不直接比较 `newConfig.colorMode`**：
在 `@Entry` 组件里该回调参数的实际类型与 `@ohos.app.ability.Configuration`
的声明不完全一致，直接跟 `ConfigurationConstant.ColorMode` 比会被 TS
判为「string 与 ColorMode 无重叠」。改为统一走 `prefersDark()`，
把类型细节收敛到一个地方。

## 三、这次修掉的问题：硬编码的浅色值

深色模式下最容易漏的不是背景色（那些都走了主题），
而是**为浅色背景设计的"深色文字 / 浅色底"**。它们编译期毫无警告，
只有真机上切到深色才看得出来。

实测发现并修复的 4 处：

| 位置 | 原值 | 问题 | 修法 |
|---|---|---|---|
| 成绩分档文字 | `#0B8A4B` `#1F86C7` `#C77700` `#C62828` | 深绿/深红在深底上几乎看不见 | 新增 `scoreExcellent/Good/Fair/Poor`，深色下提亮为 `#4ADE80` `#5FB3E0` `#F5A623` `#EF6B6B` |
| 学期平均分徽标底 | `#DCF3E6` `#DCEEF9` `#FBEFD9` `#F9DEDE` | 浅底在深色页面里亮得刺眼 | 新增 `badgeExcellent/Good/Fair/Poor`，深色下改为同色相深底 `#16351F` `#12303F` `#382B12` `#3A1D1D` |
| 设置页「离线缓存」 | `#C77700` | 同上，橙色偏暗 | 统一走新增的 `warning` |
| 课表「自主」标签 | `#D6F3E2` 底 + `#0B6B3A` 字 | 同上 | 新增 `chipSelfStudyBg/Text` |

**设计原则**：深色变体**保持同一套色彩语义**（绿=优秀、蓝=良好、橙=及格、红=不及格），
只把明度反过来 —— 浅色主题是「浅底 + 深字」，深色主题是「深底 + 亮字」。

## 四、课程色块：不需要为深色另做一套

课表格子用的是固定的 14 色调色板（见 `CourseColors.ets`），
文字颜色由 `Theme.onCourseColor(hex)` 按**相对亮度**自动选黑或白。

所以同一个色块在浅色/深色主题下都保持原色，文字也始终可读 ——
这套机制天然适配两种主题，不用额外处理。实测深色下表里
紫色 / 黄绿 / 橙色 / 青色依然鲜艳且互不混淆。

## 六、底部系统栏的接缝处理（小白条适配）

### 问题

App 用的是**非沉浸式**布局（`setWindowLayoutFullScreen(false)`），
好处是内容自动避开状态栏和底部导航条，标题不会顶到时间底下。
代价是**系统栏区域由系统自己上色**，和 App 背景对不上。

实测（深色模式）：

```
App 底部导航栏      #1A1D22
系统导航条区域       #000000   ← 两种深色相邻，肉眼可见一条分界线
```

浅色模式两边都是白，所以**这个问题只在深色下暴露**。

### 排查：`navigationBarColor` 没用

第一版按直觉设了 `setWindowSystemBarProperties({ navigationBarColor: ... })`，
状态栏生效了，底部却纹丝不动。查 hilog 看到真相：

```
WMSImms: update prop ..., prop:[5,true,"#FF101215","#FFECEEF1",false,false,null]
                                                                          ↑
                                                          导航条颜色这一项是 null
```

**手势导航模式下 `navigationBarColor` 会被系统忽略**。加日志才发现的，
光看代码和「接口调用成功」的假象会一直查不出来。

### 解法：用 `setWindowBackgroundColor`

底部导航条区域透出的其实是**窗口背景色**，所以改它才有效：

```
win.setWindowBackgroundColor(Theme.colors(isDark).surface)
```

取 `surface` 而不是 `background` 是关键：紧邻系统栏的是**底部导航栏**，
它的颜色就是 `surface`，窗口背景与它一致，接缝才彻底消失。
（顶部状态栏由 `statusBarColor` 单独负责，不受影响。）

配合状态栏也一起设，两端都连续：

| 区域 | 取色 | 效果 |
|---|---|---|
| 状态栏 | `background` | 与页面背景一致 |
| 窗口背景（底部系统栏透出） | `surface` | 与底部导航栏一致 |

### 深浅色切换时同步更新

切主题时系统栏颜色不会自己变，所以在 `Index.ets` 的
`onConfigurationUpdate()` 里一并重新调用 `applySystemBarColors()`，
否则切到深色后底部又会露出浅色。

### 实测结果

| 模式 | 底部导航栏 | 系统栏区域 | 结果 |
|---|---|---|---|
| 深色 | `#191A1F` | `#17181D` | 连续，无接缝 |
| 浅色 | `#FFFFFF` | `#F9F9F9` | 连续，无接缝 |

## 七、后续若要加页面

1. **不要写死颜色**，一律 `Theme.colors(this.isDark).xxx`；
2. 需要新语义色时，**同时**往 `Theme.ets` 的 `LIGHT` 和 `DARK` 各加一个字段
   （接口 `AppColors` 加字段后，漏掉任何一边都会编译报错，这是有意的）；
3. 页面组件别忘了接 `@Prop isDark`，并在 `RootScreen.ets` 里透传；
4. 卡片要改色，改的是 `resources/dark/element/color.json`，不是代码；
5. 动窗口/系统栏相关的设置，改 `core/SystemTheme.ets` 的 `applySystemBarColors()`。
